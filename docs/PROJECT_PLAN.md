## 2. 프로세스 정리 (Process Definition)

### **[핵심 프로세스: 운동 커밋(Workout Commit)]**



1.  **입력 단계:** 사용자가 'Iron Chat'에 오늘 운동한 내용을 자유롭게 작성하여 전송한다.
2.  **분석 단계 (AI):**
    * 서버는 사용자의 텍스트를 수신하여 Gemini API에 전달한다.
    * AI는 텍스트를 분석하여 JSON 형태의 정형 데이터로 변환한다.
3.  **비교 단계 (Diff):**
    * DB에서 해당 사용자의 동일 종목 최신 기록을 인출한다.
    * 오늘 기록과 과거 기록을 대조하여 볼륨 상승 여부를 계산한다.
4.  **저장 및 피드백:**
    * 분석된 데이터를 DB에 영구 저장한다.
    * AI가 생성한 성장 피드백과 함께 분석 결과를 사용자 화면에 카드로 출력한다.

## 3. 요구 사항 분석 (Requirements Analysis)

### **A. 성능 및 안정성**
* **응답성:** Gemini 1.5 Flash 모델을 사용하여 텍스트 파싱 시간을 3초 이내로 유지한다.
* **정확성:** 종목 인식 오류를 줄이기 위해 별칭(Synonyms) 테이블을 활용한 하이브리드 검색을 수행한다.

### **B. 데이터 무결성**
* **회원 격리:** 모든 데이터는 `user_id`를 기준으로 철저히 분리되어야 한다.
* **단위 표준화:** 모든 중량 데이터는 내부적으로 **kg** 단위를 기본으로 하되, 출력 시에만 필요에 따라 변환한다.

### **C. 사용자 경험 (UX)**
* **Dark Mode:** 헬스장의 어두운 환경과 배터리 효율을 고려한 다크 테마를 기본으로 한다.
* **수정 가능성:** AI는 언제나 틀릴 수 있음을 전제로, 모든 파싱 결과 옆에 즉시 수정 버튼을 배치한다.

## 4. 분석/설계 (Analysis & Design)

### **A. 시스템 아키텍처**


* **Frontend:** Next.js (PWA 지원으로 모바일 웹뷰 최적화)
* **Backend:** Spring Boot 3.x (Spring AI 라이브러리 활용)
* **Database:** PostgreSQL (시계열 데이터 및 JSONB 지원)
* **AI Engine:** Google Gemini API

### **B. 주요 도메인 로직 (점진적 과부하 계산)**
특정 종목의 성장을 판단하기 위해 추정 1RM 공식을 활용한다.
$$Estimated\ 1RM = Weight \times (1 + \frac{Reps}{30})$$
이 지표가 지난 세션 대비 상승했다면 **'성장(Growth)'**으로 로그를 남긴다.
